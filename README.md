# conveer-video — конвейер видео TOKENFALL

Конвейер записывает видео всех моментов игры, где звучит музыка, и витрины атак всех боссов. Так музыку и атаки можно проверить, не проходя игру. Каждая сцена — отдельный MP4 со звуком:

* бои с боссами всех уровней сложности;
* все атаки каждого босса по очереди, с подписью (сцены `attacks_<босс>`);
* смерть и победа с экранами итогов;
* все сюжетные ролики;
* все фоновые темы биомов;
* титул, Убежище, галерея, смены глав.

В кадре есть панель музыки: какие треки звучат, их громкость и позиция. Это помогает увидеть кроссфейды и джинглы. В конце получается отчёт `out/index.html`: видео подряд, журнал музыки каждой сцены и проверка треков (громкость, длина, формат).

Видео звучит **так же, как игра**. Конвейер не имитирует логику музыки, а вызывает код игры:

* `MusicDirector` и `MusicFlow` — кроссфейды, джинглы, тема босса, возврат фона;
* `ChipSynth` — звуковые эффекты и запасные петли;
* `GameSounds` — какое событие что озвучивает;
* симуляцию забега и ролики.

Если в игре переход звучит плохо, в видео он звучит так же.

## Где лежат папки

Конвейер и игра лежат **в одной папке, рядом**:

```
любая-папка/
├── conveer-video/   ← этот репозиторий
└── game-token/      ← исходники игры (git clone …/game-token)
```

Нужна версия игры с папкой `Assets/Scripts/Art/Audio` (ветка `domi/wizardly-pascal-8ue4uf` или новее). Сборка проверит это сама.

Путь к игре задаётся в `conveer.json` → `"gameRoot": "../game-token"`. Путь считается от папки конвейера. Если игра лежит в другом месте, поменяйте `gameRoot`: можно указать абсолютный путь.

## Что нужно

* **.NET SDK 8** — `dotnet --version`.
* **ffmpeg** с libx264:
  * Windows: сборка «full» с gyan.dev или `winget install ffmpeg`;
  * Linux: `apt install ffmpeg`;
  * macOS: `brew install ffmpeg`.

  Если в сборке есть libass, русские субтитры роликов вшиваются в кадр. Иначе они идут отдельной дорожкой — включите её в плеере.

## Запуск

Windows:

```bat
run.cmd                  :: все сцены
run.cmd boss_* death     :: только бои с боссами и смерть
run.cmd list             :: список сцен
run.cmd --quick cell_01  :: быстрый черновик 640×360
```

Linux / macOS:

```bash
./run.sh
./run.sh boss_* death
./run.sh list
./run.sh tracks          # только проверка треков и отчёт, без видео
```

Скрипт сам соберёт конвейер вместе с исходниками игры из `gameRoot` и запустит его. Если нужно вручную:

```bash
dotnet build -c Release -p:GameRoot=../game-token
dotnet bin/Release/net8.0/Conveer.dll [сцены…] [--quick] [--no-analyze] [--config путь/conveer.json]
```

Все 42 музыкальные сцены (без личных треков) дают около 35–40 минут видео. На обычном ПК их запись занимает около 20–30 минут, плюс минута на анализ громкости треков. Витрины атак (`attacks_*`) добавляют ещё 38 сцен, около 11 минут видео.

## Что получается

```
out/
├── index.html      ← открыть в браузере: все видео, журнал музыки, проверки, таблица треков
├── report.md       ← то же самое текстом
├── videos/*.mp4    ← по видео на сцену
└── logs/           ← журнал музыки каждой сцены (.txt) и её результат (.json)
```

Можно перезаписывать только часть сцен (`./run.sh boss_*`): отчёт всё равно соберётся по всем сценам, записанным раньше. У каждой сцены видно время записи.

Пример журнала (сцена `boss_tier1`):

```
00:00.0  вход bg_cache, кроссфейд 1.2 с
00:06.0  — вход к боссу great_captcha
00:06.0  вход boss_tier1, кроссфейд 0.6 с
00:53.1  — босс повержен: great_captcha
00:53.1  джингл sting_boss
00:53.1  через 4.8 с вход bg_cache с 6.0 с, кроссфейд 2.0 с
00:57.9  джингл уходит за 1.0 с
```

**Панель музыки в кадре** (слева внизу):

* `> ИМЯ` — играющий трек, полоска показывает его громкость;
* `IN` / `OUT` — трек входит или уходит в кроссфейде;
* `WAIT` — трек ждёт своей очереди;
* `* ИМЯ` — джингл;
* `SYNTH` — файла нет, звучит процедурная петля игры.

Справа внизу — имя сцены и таймкод.

## Сцены

| Сцена | Что проверяет |
|---|---|
| `title` | тема титула с демо-забегом |
| `intro` | пролог при запуске → переход к титулу |
| `hub` | тема Убежища → портал → тема Кэша |
| `bg_cache` … `bg_localhost` | каждая из 16 фоновых тем в своём биоме |
| `biome_<ключ>` | личный трек биома — появляется, если такой файл добавлен |
| `boss_mini`, `boss_tier1` … `boss_tier4`, `boss_delirium`, `boss_oom`, `boss_secret` | бой с боссом каждого уровня: фон → тема босса → победа → `sting_boss` → фон продолжается с того же места |
| `boss_<ключ>` | личный трек босса — появляется, если такой файл добавлен |
| `death` | смерть → `sting_defeat` → уход в Убежище (джингл тут же затихает) |
| `victory` | победа → `sting_victory` → уход в Убежище |
| `cell_01` … `cell_10` | ролик каждой клетки памяти → экран итогов → Убежище |
| `ending` | концовка → экран итогов → Убежище |
| `gallery` | ролик из галереи → снова тема титула |
| `transitions` | забег по главам 1 → 10: все смены фоновой темы подряд |
| `attacks_<ключ босса>` | витрина атак: босс по очереди показывает каждую свою атаку (38 боссов и мини-боссов, 127 атак) |

Бой с боссом укорочен: босс теряет здоровье не медленнее графика, около 50 с, это `seconds.bossFight`. Урон идёт обычным путём игры, поэтому фазы и неуязвимость между ними работают как в забеге. Герой в боях неуязвим, кроме сцены `death`.

## Витрины атак боссов

У каждого босса свои атаки, и ни одна не повторяется у другого. Сцены `attacks_*` нужны, чтобы проверить это глазами и оценить, как выглядят эффекты.

```bash
./run.sh attacks_*                  # все 38 витрин, около 11 минут видео, запись — 4–5 минут
./run.sh attacks_crypto_whale       # один босс
./run.sh --quick attacks_colossus   # быстрый черновик 640×360
```

Как устроена витрина:

* Комната босса на его этаже и в его биоме, с препятствиями и правилами биома. В тёмных биомах темно, видны свет героя и лампы.
* Босс по очереди показывает каждую свою атаку: сначала обычные на первой фазе, затем атаки ярости. Перед яростью босс переходит на фазу ярости, потому что атаки сильнее на поздних фазах.
* Своих атак между показами босс не начинает. После каждой атаки комната очищается: исчезают пули, зоны, лучи и призванные враги. Так следующая атака видна отдельно.
* Сверху — номер атаки, её название и описание по-английски: в пиксельном шрифте игры нет кириллицы. Русские названия есть в журнале сцены в отчёте: `атака 2/3: «Я не робот» (NotARobot) — …` с таймкодом.
* Героем управляет бот-уклонист, тот же, что в тесте `BossAttackTests`. Он не стреляет, а только уходит от опасности: зон, пуль с упреждением на полсекунды, лучей и касания. Здоровье ему возвращается. Если бот получает урон, атаку стоит проверить: её трудно прочитать.

В кадре всё рисуется так же, как в игре (`WorldView`):

* зоны атак (круги, кольца с проходом, секторы, полосы, прямоугольники, «вся комната, кроме островков»): пока зона предупреждает, она мигает всё чаще, в момент удара вспыхивает белым;
* формы вражеских пуль: сферы, квадраты, треугольники, звёзды… Острые летят носом вперёд, звёзды и крестики крутятся;
* лучи, молнии, дуги ударов, ударные волны, угли и ядовитые лужи на полу;
* темнота «Тишины» Шумового хора.

## conveer.json

| Поле | По умолчанию | Что это |
|---|---|---|
| `gameRoot` | `../game-token` | папка игры (относительно конвейера или абсолютный путь) |
| `output` | `out` | куда складывать видео и отчёт |
| `ffmpeg`, `ffprobe` | `ffmpeg`, `ffprobe` | пути к программам, если их нет в PATH |
| `width`, `height`, `fps` | 1280, 720, 30 | размер и частота кадров видео |
| `crf`, `preset` | 20, `veryfast` | качество и скорость кодирования H.264 |
| `subtitles` | `burn` | `burn` — вшить в кадр (нужен libass), `soft` — отдельной дорожкой, `off` — без субтитров |
| `language` | `ru` | язык субтитров: `ru` или `en` |
| `volumes` | 0.9 / 0.5 / 0.8 | общая громкость, музыка и эффекты — как ползунки в настройках игры |
| `seconds` | см. файл | длительность частей сцен: титул, биом, бой с боссом, экран итогов… |
| `scenes` | `["*"]` | какие сцены писать по умолчанию: имена или шаблоны `boss_*` |
| `analyzeTracks` | `true` | мерить громкость треков (EBU R128) для отчёта |
| `seed` | 7 | сид выбора вариантов треков (`bg_cache_2` …) |

## Проверка треков в отчёте

Для каждого файла из `Assets/Resources/Music` отчёт показывает длину, кодек, громкость (LUFS) и пик. Он предупреждает, когда:

* трека нет — и что звучит вместо него;
* внутри `.ogg` на самом деле MP3;
* громкость сильно отличается от рекомендованных −16 LUFS;
* джингл слишком длинный (в игре он уходит, как только вступает музыка);
* у трека тихое вступление: бой с боссом не должен начинаться в тишине, а фон — после смены биома;
* у трека долгое затухание в конце: на шве петли будет провал громкости, игра сводит конец с началом за 3 с;
* трек ролика короче самого ролика;
* в папке лежит файл, которого игра не знает.

Список треков и промпты для генерации — `game-token/docs/15-soundtrack.md`.
